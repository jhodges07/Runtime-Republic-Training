Welcome back to Runtime Republic. In Episode 2 we covered the habits. Today we turn those habits into machinery. Workflows you repeat. Cheat codes that save you hours. And automations that keep working while you sleep.

Let's start with the master workflow. I call it the four-beat loop, and it is really plan, do, check, act, the same cycle you built into Liberty Cadence.

Beat one: plan. Before Claude writes a single line, ask it for a plan. In Claude Code there is a planning mode built for exactly this. Read the plan like a design review. Is the scope right? Does it respect your control documents? Change the plan, not the code. A minute here saves an hour later.

Beat two: do. Claude makes one logical change. Just one.

Beat three: check. Tests run. You read the difference between the old and new code. For writing, you read it out loud. If it fails, it goes back.

Beat four: act. Commit with a clear message, update your architecture status file, and choose the next change.

That loop is the heartbeat of everything else.

Now, the workflows. Here are four you can build your business on.

Workflow one: the new project in ten minutes. You already built the hard part, your Control Engineering Template. On GitHub, you click Use this template, run the setup script with a project name, and you have numbered control documents, a CLAUDE.md, a pull request template, and automated checks before you write a line of code. Then you open Claude Code and say: "Read CONTROL 01 and help me fill in the goal and scope." Every app you start, Know Your Loop, Liberty Cadence, whatever comes next, starts disciplined.

Workflow two: the phone app pipeline. Here the smart move is patience. Get the LLC its own Apple developer account first, and ship every build from it, starting with the very first alpha. Moving an app from a personal account to a company account later can be done, but it means new signing, new keys, and a list of things that do not move over cleanly. So until the company account is ready, keep building and testing on your own phone, straight from your computer. Nothing goes out to testers until it can go out under the LLC's name. Then alpha, beta and final releases all live in one place, on the same backend runtime and API. The cheat code here is to write that plan into a control document now. Who owns the account, bundle identifiers, signing, push notification keys, where the backend lives. Then Claude can help you set it up step by step, instead of discovering surprises the week you launch.

Workflow three: the content engine. You write essays in Runtime Republic Training. Each one needs approval. Each one needs a supporting image with BlueprintLiberty.com at the bottom center and RuntimeRepublic.com right below it. Then Essay Audio Runtime narrates the approved text, exactly as written. Then it publishes to your two websites. That is a pipeline: draft, approve, image, narrate, publish. Claude helps at every stage, but a human signs off at the approve stage. Once it is written down, it runs the same way every time, and you can hand any stage to a helper.

Workflow four: the living dashboard. Your Kansas tax foreclosure tracker is meant to update weekly, starting with the most populous counties. That is a perfect job for a scheduled task. Claude can run on a schedule, gather the latest public filings, update the data, and refresh the dashboard, then tell you what changed. You review. You publish. A once-a-week chore becomes a five-minute review.

Now for the cheat codes. These are short phrases that change the quality of what you get back.

Cheat code one: "Before you start, ask me the three questions that would most change your answer." This flips the conversation. Claude surfaces the assumptions you forgot to state.

Cheat code two: "Show me the plan, not the code." Review the thinking before the work.

Cheat code three: "Argue against this." Ask Claude to be the toughest critic of your idea, your bill draft, or your pricing. It is much easier to hear from a machine at midnight than from a customer after launch.

Cheat code four: "Which control document governs this?" If Claude cannot point to one, either the change is out of scope or you need a new control document.

Cheat code five: "End with a verification checklist." Every answer finishes with the exact steps you should take to confirm it is right.

Cheat code six: "Turn this into a skill." When you notice you have explained the same procedure three times, ask Claude to package it as a skill. A skill is a saved set of instructions Claude loads whenever that kind of task comes up. Write your essay approval rules once, and every future essay follows them.

Finally, automations. The deepest lever is connecting Claude to your other tools. That is what MCP, the Model Context Protocol, does. It is a standard way to plug tools into AI. You are already building on it. Your AI Coordination Service exposes read-only tools so different AI assistants can share a coordination ledger without stepping on each other. Your Universal CAD MCP points the same idea at design software. That is the future: not one chat window, but a small fleet of tools, each with clear permissions, all governed by your rules.

And on GitHub, automations are free and powerful. Every pull request can run your control-document checks and your tests automatically. Nothing merges unless the checks pass. Claude can even pick up a GitHub issue, do the work on a branch, and open a pull request for you to review.

Let's recap. The four-beat loop: plan, do, check, act. Four workflows: new project from template, phone app pipeline, content engine, living dashboard. Six cheat codes. And automations through scheduled tasks, MCP, and GitHub checks.
