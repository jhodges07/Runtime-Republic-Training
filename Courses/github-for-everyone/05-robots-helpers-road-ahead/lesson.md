Over the last four essays, we've learned that GitHub is a giant online library for building things together, that it began as a side project in 2008, that it has its own toolbox of words like commit, branch, and pull request, and that open source lets people share their recipes with the whole world. Today, in our last main essay, we'll look at where GitHub is now, and where it might be heading.

Let's start with how big it has become. Each year, GitHub publishes a report called Octoverse, a kind of yearly report card. In late 2025, it said more than 180 million developers were building on GitHub, with about one new developer joining every single second, and roughly 230 new repositories created every minute. Think about that. In the time it takes you to listen to this sentence, several new people somewhere in the world have just joined.

Now let's talk about robots. Not the metal kind with arms and legs, but helper programs that do jobs automatically.

One of the most useful helpers on GitHub is called Actions. Imagine your class cookbook from Part Three. Every time someone adds a recipe, wouldn't it be nice if a helper automatically checked the spelling, made sure every recipe listed its ingredients, and then printed a fresh copy of the cookbook? That's what GitHub Actions does for code. Programmers write a set of instructions, and every time someone makes a change, the robot helper runs tests, checks for mistakes, and can even publish the finished product. It's like having a tireless assistant who never sleeps.

But the biggest change of all has been artificial intelligence, often called AI. AI is a kind of computer program that has learned patterns from enormous amounts of information, so it can make predictions and help with tasks.

In 2021, GitHub introduced an AI helper called Copilot. The name makes sense. On an airplane, the copilot sits next to the pilot and helps fly the plane. GitHub Copilot sits next to the programmer and helps write code. You start typing, and Copilot suggests what might come next, a bit like how your phone suggests the next word in a text message, but for whole chunks of a program.

Copilot became very popular. In early 2026, GitHub said it had more than 4.7 million paying Copilot subscribers, up 75 percent from the year before. And the helpers have grown more capable. They don't just suggest the next line anymore. Some can now take on an entire task, like fixing a bug or adding a feature, and then open a pull request for a human to review. In October 2025, GitHub announced something called Agent HQ, which it describes as a place where AI helpers from many different companies, including Anthropic, OpenAI, and Google, can work inside a person's GitHub project.

Notice something important there. Even when an AI helper does the work, it still sends a pull request. A human still reviews it, asks questions, and decides whether to merge it. The good manners we learned about in Part Two still matter.

GitHub itself has changed too. In August 2025, its leader, Thomas Dohmke, announced he was leaving, and said GitHub's leadership would continue within a part of Microsoft called CoreAI. In other words, GitHub moved closer to Microsoft's big push into artificial intelligence.

Not everyone thinks all of this is a good thing, and it's important to hear the different sides.

Some people are excited. They say AI helpers let programmers build things faster, help beginners learn, and handle boring jobs so humans can focus on creative ones.

Others have real concerns. One big question is about fairness. AI helpers learned by studying huge amounts of public code, much of it shared on GitHub under open source licenses. Remember those licenses from Part Four, the rules that say how code can be used? Some programmers asked, "If an AI learned from my code, is it following my rules?" In 2022, a group of programmers even went to court over this question. Other people worry about mistakes, since AI can sound confident while being wrong. And some wonder how these tools will change jobs for programmers in the future.

There's also a lesson about depending on one place for everything. When so many people rely on a single website, any hiccup affects millions. GitHub has had outages, times when parts of it stopped working for hours, and each one reminds people that even giant hubs need backup plans. That's one reason Git itself is so clever. Because every person who clones a project has a full copy, the work isn't lost even if the website goes down.

So what does the future look like? Nobody knows for sure. But some things seem likely to stay true. People will keep needing to work together on big projects. They'll keep needing to save their work, try ideas safely on branches, talk through changes, and decide together what goes into the final version. Whether the helper is a classmate, a stranger across the ocean, or an AI, those basic ideas, commit, branch, pull request, review, and merge, are about something deeper than code. They're about how a group of people can build something together, fairly and in the open.

Let's review our whole series. GitHub is a place where people store projects and build them together, using Git, the magical save button invented by Linus Torvalds. It began in 2008 as a side project and was bought by Microsoft in 2018. Its toolbox includes repositories, commits, branches, pull requests, forks, and issues. It became the home of open source, where people share their work freely. And today, it's being reshaped by robot helpers and artificial intelligence, which brings both exciting possibilities and serious questions.

Here's your final thinking question. If an AI helper suggested a change to your project, what would you want to check before you said yes?
