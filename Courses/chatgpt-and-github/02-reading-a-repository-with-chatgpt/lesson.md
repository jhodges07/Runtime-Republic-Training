# Reading a Repository with ChatGPT

Welcome back to Runtime Republic. Last time, we connected ChatGPT to GitHub. Today we use it to read a public project carefully, without handing over our judgment.

Start by setting the ground rules. ChatGPT lets you save custom instructions, or set up a project with its own instructions. Here's a set that works well for civic work. Say or type: "Act as a careful reviewer. Name the repository and file behind every claim. Say plainly when something is unknown. Never invent laws, numbers or sources. Point out weaknesses, not just strengths."

Why those rules? Because an assistant that only agrees with you isn't reviewing anything.

Now three prompts that do most of the work.

The first builds a map. Say: "Using my copy of the Runtime Republic Training repository, list the main files in the One-Hour Rule course, what each one is for, and what I should read first." Name the repository in your prompt. ChatGPT finds repositories by name.

The second asks for receipts. Say: "Summarize this draft in one paragraph. Then list each claim, with the file it came from." Now every sentence can be checked.

The third asks the hard question. Say: "What are the three strongest objections to this proposal, and what in the repository answers them, if anything?" This is where an assistant earns its keep. It surfaces the gaps. Then follow up: "Which of those objections did you find in the repository, and which did you infer?" That one question separates evidence from guesswork.

Here's a bonus prompt for sharing what you learn. Say: "Explain this proposal to a neighbor who has never heard of it, in five sentences, with no jargon. Mark any sentence you couldn't find in the repository." Then check it against the source before you post it anywhere. Short, honest explanations travel further than long ones.

Then the habits. Open the files ChatGPT points to, especially for laws and numbers. If you hold public office, your prompts about official business may be public records, so write them professionally. And if a repository was just updated, give it a few minutes before asking about the newest version.

Let's recap. Set reviewer rules. Ask for a map, a summary with receipts, and the strongest objections. Name the repository in your prompts. Check the sources yourself. And keep it professional.

Next time, we'll look at proposing changes, with OpenAI's separate tool for that, and the rule that a human always makes the final call.
