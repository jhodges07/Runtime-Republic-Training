# Reading a Repository with Claude

Welcome back to Runtime Republic. Last time, we connected Claude to GitHub. Today we use it. The goal is simple: read a public project faster and more carefully than you could alone, without letting the AI do your thinking for you.

Start by giving Claude a role and some rules. In a Claude Project, there's a place for instructions that apply to every chat. Here's a set that works well for civic projects. Say or type: "Act as a careful reviewer. Cite the exact file and section for every claim. Say plainly when something is unknown. Never invent laws, numbers or sources. Point out weaknesses, not just strengths."

That last part matters. An assistant that only agrees with you is a mirror, not a reviewer.

Now three prompts that do most of the work.

The first is the map. Say: "List the main files in this repository, what each one is for, and which ones I should read first." This turns a pile of files into a reading plan.

The second is the summary with receipts. Say: "Summarize this draft in one paragraph. Then list each claim you made, with the file and section it came from." Now you can check every sentence against the source.

The third is the hard question. Say: "What are the three strongest objections to this proposal, and what in the repository answers them, if anything?" This is where Claude helps most. It finds the gaps you'd rather not see. Then follow up: "Which of those objections did you find in the repository, and which did you infer?" That one question separates evidence from guesswork.

Here's a bonus prompt for sharing what you learn. Say: "Explain this proposal to a neighbor who has never heard of it, in five sentences, with no jargon. Mark any sentence you couldn't find in the repository." Then check it against the source before you post it anywhere. Short, honest explanations travel further than long ones.

A few habits keep you safe. Open the sources Claude cites, especially for laws and numbers. If you hold public office, remember that your prompts about official business may be public records, so write them as if a reporter might read them. And sync the project before each session, so you're not reviewing yesterday's draft.

Let's recap. Give Claude a reviewer's role and rules. Ask for a map, a summary with receipts, and the strongest objections. Check the sources yourself. And keep your prompts professional.

Next time, we'll go one step further: using Claude to propose a change, safely, with a human always making the final call.
