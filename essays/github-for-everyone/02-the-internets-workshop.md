# How a Late-Night Idea Became the Internet's Workshop

- **Series:** GitHub for Everyone, Part 2
- **Date:** 2026-10-28
- **Audience:** Ages 10 and up
- **Format:** Read aloud
- **Status:** Draft

---

Last time, we learned that code is a recipe for computers, that Git is a magical save button, and that GitHub is a giant online library where people build things together. Today, we're going to travel back in time and find out how GitHub was born.

Our story starts in San Francisco, California, in 2007. Two programmers named Chris Wanstrath and Tom Preston-Werner kept running into each other at a meetup, which is a gathering where people who love the same thing come together to talk about it. These two loved a programming language called Ruby.

One night, Tom showed Chris a small project he'd been tinkering with. It was an early idea for a website where people could share their Git projects easily. Chris loved it. They started working on it together on nights and weekends, while still holding their regular jobs. Soon, two more friends joined them, a programmer named PJ Hyett, and another named Scott Chacon, who would later become one of the best teachers of Git in the world.

Here's something surprising. These founders didn't start in a fancy office with lots of money. They built GitHub in coffee shops and apartments. They didn't take money from big investors at first. Instead, they made GitHub free for anyone sharing projects publicly, and they charged a small fee to people and companies who wanted to keep their projects private. That simple idea paid the bills. For about four years, GitHub grew using only its own earnings. That's a bit like running a lemonade stand so well that you never need to borrow money from your parents.

GitHub officially opened to the public in April 2008. And people loved it right away. Why? Because it turned something hard into something friendly.

Before GitHub, if you wanted to help with someone's project, you usually had to email them your changes and hope they noticed. GitHub made this much easier with something called a pull request. A pull request is like raising your hand and saying, "I made an improvement. Would you please pull it into your project?" Everyone can see the change, talk about it, and suggest fixes, all in one place. This one idea changed how people around the world work together on code.

GitHub also added something fun. It gave every user a profile page, a bit like a scrapbook of all the projects you've worked on. Suddenly, programmers could show off their work the way an artist shows a portfolio. Some people even got jobs because an employer saw their GitHub page.

And GitHub had a mascot. Its name is the Octocat. It has the head of a cat and the legs of an octopus. Yes, really. It became so famous that people made stickers, t-shirts, and even costumes of it.

Year after year, GitHub grew bigger. Students joined. Scientists joined. Huge companies joined. Governments even started using it. By 2012, it had grown so much that it finally accepted a large investment, one hundred million dollars, to help it grow even faster.

Then, in 2018, something big happened. Microsoft, one of the largest technology companies on Earth, announced it was buying GitHub. The price was seven and a half billion dollars. That's a seven, followed by nine zeros.

Not everyone was happy. Many years before, Microsoft had been known for keeping its code secret and sometimes competing hard against free, shared software. Some programmers worried that Microsoft would change GitHub or make it worse. A number of people even packed up their projects and moved them to other websites, like GitLab.

But something interesting happened next. Microsoft had changed a lot over the years, and it now shared much of its own code openly. After the purchase, GitHub kept running much as it had before. In fact, a few months later, GitHub made private projects free for everyone, something people had wanted for a long time. Many of the worried programmers decided to stay, and many new people joined.

So let's look back at what we learned today. GitHub started as a side project by a few friends in San Francisco. It opened in 2008, grew by charging only for private projects, and became famous for pull requests, profile pages, and a funny half-cat, half-octopus mascot. And in 2018, Microsoft bought it for seven and a half billion dollars, which caused some worry, but GitHub kept growing.

In Part Three, we'll roll up our sleeves and learn the basic words and tools of GitHub, things like repositories, commits, forks, and issues. Don't worry if those sound strange. By the end, they'll feel as familiar as the parts of a bicycle.

Here's your thinking question for today. Why do you think letting anyone see and suggest changes to a project might make that project better?
